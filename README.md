# 展会报名 · 字段版本协同与快照迁移模拟器

每月换字段、金额与资质校验常对不上的问题，按「定义—规则—快照按版本协同」重做。

## 四条核心诉求如何落地

1. **字段定义 / 联动规则按版本协同**
   - 字段、联动规则（显隐、必填、金额/资质条件）、金额计算规则都挂在不可变版本上；改版在「草稿」里进行。
   - 字段**移走或改类型/改选项**时，`recomputeRules` 立即让引用它的规则失效重算，标注原因（字段已移走、类型不匹配、选项已删除、`等于` 误用于金额字段等）；改名不影响引用。失效规则保留在草稿中可重新绑定修复，运行态只执行生效规则。

2. **已提交快照按原版解释；升级时能映射的回填、不能映射的列出待补**
   - 快照冻结 `versionId`，`interpretSnapshot` 永远取该版本的字段定义解释（如旧 `amount: "14400"` 按旧版转数字，新版加 C 级资质不会让旧 B 级数据失效）。
   - 发起升级时同名字段自动映射，按类型兼容矩阵（text 可转出、任意类型→text、number/select/date 互转不兼容）做值转换；新增必填字段、不兼容类型、转换值非法（如「星辰科技」转日期）进入「待补」清单，可手动改映射或补录。

3. **两人同版本并发提交**
   - 版本带 `revision` 乐观锁：提交时基线仍是最新版本 → 先入库发布；对方已发布 → 后提交者**保留草稿并看到字段级冲突**（类型/必填/选项/删除差异）。
   - 「以最新版为基线合并」：同名字段以先生效版本为准，草稿独有新增字段保留，规则重新校验后续改。

4. **回填失败可续、重开有全景待办**
   - 迁移是持久化任务：回填接口失败（面板上有模拟开关）时状态置 `failed`，已回填数据和补录值全部留住，可反复重试；部分补齐时保持 `pending_backfill`，全部补齐才 `done`。
   - 所有状态写 localStorage；重开后「总览 / 待办」集中展示：待修复规则、冲突草稿、待补/失败的迁移记录，一键跳转处理。

## 关键文件
- `src/engine.ts`：纯函数内核——规则失效重算、快照原版解释、类型转换与映射评估、运行态显隐/校验/金额计算（含循环依赖检测）、并发字段冲突分析。
- `src/store.ts`：Redux 状态——版本/草稿/快照/迁移任务，乐观锁提交、失败可重试回填、localStorage 持久化。
- `src/Designer.tsx`：字段拖拽与类型编辑、失效规则提示与重新绑定。
- `src/MigrationPanel.tsx`：快照原版解释、映射调整、待补录入、回填与重试。
- `src/Runtime.tsx`：按选中版本渲染动态报名表，联动显隐、金额自动计算、提交校验、提交即冻结快照。
- `scripts/smoke.ts`：48 项端到端断言（`npx tsx scripts/smoke.ts`）。

## 建议演示路径
1. 两位运营各开一份草稿；甲把「申请金额」改成文本或移走「资质证书编号」→ 观察引用规则立即标红失效，重新绑定后恢复。
2. 甲先提交 → v3 生效；乙再提交 → 保草稿看冲突 → 合并到最新版续改。
3. 旧快照页：对八月快照发起升级到 v2 → 电话/单价自动列为待补；打开「模拟下一次回填失败」→ 执行回填失败 → 补录 → 重试至完成。
4. 刷新页面 → 总览仍显示未完成任务与冲突草稿。
5. 运行态：C 级资质不填证书编号会被拦；金额=面积×单价自动算出；金额为空时开票日期隐藏。
